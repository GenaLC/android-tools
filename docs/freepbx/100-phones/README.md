# 100 GSM-шлюзов на одном FreePBX

Готовая конфигурация FreePBX на любое число телефонов (в комплекте — 100).
SIP-аккаунты агента и телефона вы создаёте сами; здесь всё, что настраивается
**сверх** них: dialplan, транки, исходящие маршруты и — если нужно — файлы
эндпоинтов.

---

## 1. Что создаётся на один телефон

| Объект | Где | Имя | Зачем |
|---|---|---|---|
| Эндпоинт | `pjsip.endpoint_custom.conf` | `100N` | SIP-аккаунт телефона |
| AOR | `pjsip.aor_custom.conf` | `100N` | адрес регистрации |
| Auth | `pjsip.auth_custom.conf` | `100N-auth` | пароль (свой на каждый телефон) |
| DID | `phones.csv` → `own_number` | `380939104994`… | номер, по которому PBX адресует этот телефон |
| Агент | SIP-расширение | `40181`… | кому звонить по входящему DID и чьи исходящие идут через этот телефон |
| Транк | `trunks` (БД) | `gsm-gateway-100N` | исходящая нога: `PJSIP/$OUTNUM$@100N` |
| Маршрут | `outbound_routes` (БД) | `gsm-100N` | маршрут исходящих агента `401NN` через телефон `100N` |
| Правило DID | `extensions_custom.conf` | — | `DID → агент` |

### Как это работает

**Входящий GSM-звонок (абонент → агент).** Телефон принимает звонок с SIM и
шлёт INVITE на PBX: в Request-URI — свой DID (значение «Own number» слота SIM),
в `P-Asserted-Identity` — номер абонента. PBX попадает в `[from-gsm-gateway]`,
снимает ведущий плюс и уходит в таблицу `[from-gsm-gateway-did]`, где DID →
агент. Дальше `Dial(PJSIP/40181)`.

**Исходящий звонок (агент → абонент).** Агент звонит наружу; маршрут FreePBX
по `match_cid` пропускает его CallerID, транк звонит в эндпоинт телефона
`PJSIP/<номер>@100N`, и телефон набирает этот номер через SIM.

### Два разных CID — не путать

В маршруте FreePBX два независимых поля с CallerID:

| Поле | Колонка БД | Роль | Значение здесь |
|---|---|---|---|
| **Route CID** | `outbound_routes.outcid` | CallerID, который PBX подставляет в исходящий INVITE к шлюзу (рендерится как `TRUNKCIDOVERRIDE=`) | **номер телефона** (`own_number`) |
| **CallerID** в строке dial pattern | `outbound_route_patterns.match_cid` | ограничение: какие CallerID могут пользоваться маршрутом (рендерится как `_+X./40181`) | **номер агента** (`401NN`) |

Почему Route CID = номер телефона: приложение сверяет CallerID исходящего
INVITE со значением «Own number» каждого слота SIM и выбирает тот слот, для
которого совпадение единственное. То же поле «Own number» даёт DID входящего
INVITE — поэтому один номер на телефон закрывает обе задачи, и расхождение
между маршрутом и телефоном невозможно.

На телефоне с одной SIM приложение позвонит в любом случае (выбирать не из
чего), но на двух-SIM несовпадение даёт `503 No Matching SIM`.

> В старой редакции `SCALING.md` здесь было написано наоборот («Route CID —
> номер SIM»), и это была ошибка: `match_cid` — это номер агента, а Route CID
> (`outcid`) — номер, который видит шлюз. Подробности и доказательства — в
> [`../SCALING.md`](../SCALING.md) §0 и [`../STATUS.md`](../STATUS.md) §12.

### Кто кому назначен

По умолчанию связь один к одному: телефон `100N` ↔ агент `401NN` ↔ номер
`38093910499N`. Но схема это не требует:

* **Один агент на несколько телефонов** — у нескольких телефонов в `phones.csv`
  один и тот же агент. Их исходящие пойдут через телефон, который указан в
  `match_cid` соответствующего маршрута.
* **Несколько агентов на один телефон** — в `phones.csv` у телефонов разные
  агенты, а в маршруте телефона вместо номера агента пишется шаблон:
  `match_cid = 401[1-3]` (FreePBX сам добавит `_`).

## 2. Файлы

```
100-phones/
├── phones.csv                 входные данные — единственный файл, который правят
├── gen.py                     генератор: phones.csv → generated/*
├── check.py                   офлайн-проверка сгенерированного (без сервера)
├── apply.sh                   установка на сервер: бэкап, применение, проверка, откат
└── generated/
    ├── extensions_custom.conf     dialplan: DID → агент
    ├── pjsip.endpoint_custom.conf эндпоинты (только если не делаете их в GUI)
    ├── pjsip.aor_custom.conf      AOR
    ├── pjsip.auth_custom.conf     пароли
    ├── trunks-routes.sql          транки и маршруты FreePBX
    └── phone-app-settings.csv     что прописать в каждом телефоне
```

### `phones.csv`

```csv
phone,own_number,agent,peer_number,password
1001,380939104994,40181,+380507127621,008fda866b2
1002,380939104995,40182,+380507127622,e162e69f15f3
```

* `phone` — SIP-аккаунт телефона (имя эндпоинта, AOR и `auth`);
* `own_number` — номер телефона. Он же DID входящего INVITE, он же Route CID
  исходящего маршрута, он же значение, которое надо вписать в поле «Own number»
  слота SIM в приложении. Плюс можно ставить — генератор снимет;
* `agent` — SIP-расширение агента: кому звонить по входящему DID и чьи
  исходящие идут через этот телефон (`match_cid` маршрута);
* `peer_number` — справочно: номер абонента, который звонит на этот телефон.
  В конфигурации не используется, можно оставить пустым;
* `password` — пароль SIP-аккаунта. **Свой на каждый телефон**: эндпоинт
  `100N` обслуживает любого, кто знает его пароль.

Кроме телефона 1001 (он уже работает) все значения — **шаблон**: и номера, и
пароли нужно заменить на настоящие.

## 3. Порядок применения

**1. Подготовить phones.csv** — заполнить реальные DID, номера SIM и пароли.

**2. Сгенерировать:**

```bash
python3 gen.py            # читает phones.csv, пишет generated/
python3 check.py          # офлайн-проверка: ID, CID, пары, дубликаты
```

`check.py` ничего не меняет и никуда не ходит: он ловит расхождения между
`phones.csv` и сгенерированными файлами (пустой Route CID, `match_cid` не от
того агента, несовпадение числа колонок и значений в SQL, дубликаты exten).

**3. Создать SIP-аккаунты телефонов.** Два пути:

* **в GUI** (рекомендуется): Endpoint Manager или Advanced → Endpoints, по
  образцу работающего `1001`:

  ```ini
  [1002]
  type=endpoint
  aors=1002
  auth=1002-auth
  allow=ulaw,alaw
  context=from-gsm-gateway
  callerid=1002 <1002>
  dtmf_mode=rfc4733
  direct_media=no
  outbound_auth=1002-auth
  trust_id_inbound=yes
  media_use_received_transport=no
  ```

  AOR: `type=aor`, `max_contacts=1`, `remove_existing=yes`,
  `maximum_expiration=7200`, `minimum_expiration=60`, `qualify_frequency=60`.
  Auth: `type=auth`, `auth_type=userpass`, `username=1002`, пароль свой.

  Тогда файлы `pjsip.*_custom.conf` не применяйте.

* **файлами**: скопировать `generated/pjsip.*_custom.conf` в `/etc/asterisk/`
  (apply.sh сделает это сам с флагом `--with-pjsip`).

**4. Настроить приложение на каждом телефоне** (см. `phone-app-settings.csv`):

| Параметр | Значение |
|---|---|
| SIP-аккаунт | `100N` |
| SIP-пароль | из `phones.csv` |
| Own number (для слота SIM) | `own_number` из `phones.csv` — без плюса |
| Номер SIM | телефон возьмёт с карты, но лучше задать явно |

Поле «Own number» слота — то самое значение, которое стоит в Route CID
маршрута: по нему приложение выбирает SIM-слот на исходящих. Если оставить
его пустым, DID входящего возьмётся с карты SIM, а Route CID будет
сравниваться с пустым значением — на двух-SIM-телефоне исходящие перестанут
работать (`503 No Matching SIM`), на одном-SIM пройдут.

**5. Установить конфигурацию на сервер:**

```bash
scp -r 100-phones root@pbx:/root/
ssh root@pbx 'cd /root/100-phones && ./apply.sh apply'
```

`apply.sh` сам: сделает бэкап в `/root/gsm-gateway-backup/<дата>/`, поставит
dialplan, создаст транки и маршруты, выполнит `fwconsole reload` и напечатает
результат проверки.

Флаги:

```bash
./apply.sh apply --dry-run       # показать план, ничего не менять
./apply.sh apply --with-pjsip    # вместе с файлами эндпоинтов
./apply.sh apply --drop-legacy   # плюс удалить одиночную схему (транк 248, маршрут 351)
./apply.sh verify                 # только проверка
./apply.sh rollback /root/gsm-gateway-backup/20261127-150000
```

**`--drop-legacy` нужен**, если в phones.csv есть телефон `1001`: работающая
одиночная схема (транк 248, маршрут 351) описывает тот же телефон и имеет тот
же `match_cid`, что и сгенерированный маршрут 9001 — два маршрута будут
конкурировать за исходящие агента. Бэкап перед удалением делается всегда.

**6. Проверить:**

```bash
asterisk -rx "pjsip show endpoints" | grep 1002      # телефон зарегистрировался
asterisk -rx "dialplan show contexts" | grep outrt   # маршруты в dialplan
asterisk -rx "dialplan show from-gsm-gateway-did"    # таблица DID
```

и сделать контрольный звонок: агент звонит на номер абонента через телефон
`1002`, абонент отвечает — агент должен услышать абонента, телефон молчит.

## 4. Ограничения, о которых надо знать заранее

* **Локальный SIP-порт приложения фиксирован — 5062.** Два телефона за одним
  NAT (один Wi-Fi) схватят один порт: AOR-контакт каждого придётся указывать
  явно. Для телефонов в разных сетях ограничения нет.
* **Пароль на телефон свой.** Одинаковый пароль на всех — общий вход в любой из
  них.
* **`max_contacts=1`** на AOR: один телефон — один контакт. Для резерва
  (телефон с двумя сетями) нужно 2.
* **Идентификация по имени аккаунта**: `From` + `P-Asserted-Identity`, без
  `identify` и без статического IP — поэтому телефон может заходить из любой
  сети.
* **Транспорт не перечитывается на лету.** У транспорта `allow_reload=no`
  (FreePBX так пишет по умолчанию): следующая правка NAT-параметров потребует
  перезапуска Asterisk.
* **`fwconsole reload` прерывает звонки на секунду.** Планируйте на окно.
* **Идентификаторы объектов** занимают диапазон 9001…: транки `900N`, маршруты
  `900N`. На занятых номерах скрипт остановится — проверьте `SELECT MAX(trunkid)
  FROM trunks;` и `SELECT MAX(route_id) FROM outbound_routes;`.
* **Откат возвращает таблицы целиком.** `rollback` кладёт в базу дамп шести
  таблиц из бэкапа — всё, что добавили в них после бэкапа, пропадёт. Для
  точечного отката маршрутов пользуйтесь транзакцией вручную.
* **Двойной маршрут для телефона 1001.** Пока на сервере живы транк 248 и
  маршрут 351, у телефона 1001 два маршрута с одинаковым `match_cid` — см.
  `--drop-legacy` выше.

## 5. Что покрывает `extensions_custom.conf`

| Контекст | Назначение |
|---|---|
| `[from-gsm-gateway]` | вход от любого телефона: снять ведущий плюс, уйти в таблицу DID |
| `[from-gsm-gateway-did]` | таблица `DID → агент`; последним идёт catch-all с отбоем |
| `[gsm-outbound]` | ручной исходящий через конкретный телефон: сначала `Set(GSM_PHONE=100N)`, потом `Goto(gsm-outbound,<номер>,1)`. Если `GSM_PHONE` не задан — берётся первый телефон из `phones.csv` |
| `[add-gsm-forward]` | кладёт `X-GSM-Forward` — номер, который приложение должно набрать в GSM |

Обычный исходящий вызов агента через `gsm-outbound` не идёт: его маршрут
FreePBX ведёт через транк из `trunks-routes.sql`.
