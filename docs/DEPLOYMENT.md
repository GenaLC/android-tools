# Развёртывание на Cubot (X90 / X100)

Инструкция для установки собранного шлюза на рутованный телефон с Android 15.
Сервер FreePBX на этом шаге не трогаем — сначала проверяем, что телефон вообще
умеет цифровой аудио-мост.

## 0. Что понадобится

- Телефон с установленным Magisk (Superuser для «Apps and ADB»).
- USB-кабель и `adb` из `platform-tools` (уже установлен локально:
  `$HOME/Library/Android/sdk/platform-tools/adb`).
- Собранный `gsm2sip-magisk.zip` из репозитория.

## 1. Проверить, есть ли на устройстве цифровой аудио-путь

Это решающий шаг: без него шлюз работает только в акустическом режиме
(микрофон/динамик телефона, с эхом и потерей качества).

```bash
./tools/check-device-cubot.sh            # одно устройство
./tools/check-device-cubot.sh <serial>   # конкретное из нескольких
```

Скрипт не меняет состояние устройства — только читает. Отчёт содержит строку
`VERDICT:` с рекомендуемым режимом инъекции.

Что он проверяет:

| Проверка | Зачем |
|---|---|
| `ro.board.platform`, `ro.soc.model` | Определение SoC (ожидаем `mt6855v`/`aza` для X100, `mt6789` для X90) |
| `incall_music` и `Telephony Tx` в `/vendor/etc/audio_policy_configuration.xml` | Есть ли маршрут инъекции в аплинк модема |
| `TELEPHONY_TX` / `TELEPHONY_RX` в `dumpsys media.audio_policy` | Есть ли маршруты перехвата аудио разговора |
| HAL-параметры BGS через `su` | Работает ли путь MediaTek BGS-player |
| PCM-каналы захвата (`Incall Capture Stream*`) | Есть ли что читать через `tinycap` |
| IMS/VoLTE/WFC-свойства | Как оператор ведёт голос — CS, IMS/VoLTE или Wi-Fi Calling |

### Отдельно: Wi-Fi Calling

При **VoWiFi (WFC)** сотовой ноги нет вообще — голос идёт через Wi-Fi, модемного
аудио-канала не существует, мост невозможен. Если SIM заведена с WFC, его нужно
отключить в настройках оператора или на устройстве.

### Отдельно: тип сотового вызова

Классификация вызова (CS / IMS / VoLTE / WFC) видна только на живом вызове:

```bash
adb logcat -b radio | grep -Ei 'ims|mms|voip|wfc|mtc'
```

Сделайте обычный исходящий звонок и посмотрите, что пишет модем.

## 2. Установка Magisk-модуля

1. Скопировать `gsm2sip-magisk.zip` на телефон.
2. Magisk Manager → Modules → Install from storage → выбрать архив.
3. Перезагрузка. Модуль ставит APK как системное priv-app и выдаёт
   привилегированные права (`CAPTURE_AUDIO_OUTPUT`, `MODIFY_PHONE_STATE`,
   `READ_PRIVILEGED_PHONE_STATE`, `CALL_PRIVILEGED`) — без них захват аудио
   разговора невозможен, а `pm grant` их не выдаёт: это права уровня
   `signature|privileged`, а не runtime.
4. Проверить, что приложение стало системным:

```bash
adb shell pm list packages | grep callagent
adb shell dumpsys package com.callagent.gateway | grep -A3 'flags' | head -5
```

В списке `flags` должно быть `SYSTEM` и `PRIVILEGED`.

## 3. Приложение — телефонное по умолчанию

Android требует, чтобы шлюз был приложением «Телефон» по умолчанию: только так
он получает входящие вызовы и может управлять сотовой ногой.

Settings → Apps → Default apps → Phone app → GSM2SIP.

Проверка:

```bash
adb shell cmd role get-role-holders android.app.role.DIALER
```

## 4. Настройка SIP в приложении

В приложении (шестерёнка) задаются:

| Поле | Значение | Примечание |
|---|---|---|
| Server | FQDN или IP вашего FreePBX | Для TLS — обязательно FQDN, совпадающий с SAN сертификата |
| Port | 5061 | SIP over TLS. 5060 — plaintext SIP |
| Transport | TLS | По решению — прямой SIP over TLS |
| Extension | номер расширения | Например `1001` |
| Password | пароль расширения | Тот же, что в `pjsip.conf` |
| Own Number | номер SIM в строгом E.164 | Например `+4915112345678`. Без него шлюз отклонит входящий звонок (он звонит сам себе) |
| Codec | G.722 / G.711 | По умолчанию G.722; если сервер предлагает только alaw/ulaw — G.711 |

## 5. Проверка живой связи

1. Приложение должно показать статус **Online** — значит REGISTER прошёл.
2. Исходящий: с FreePBX позвонить на расширение шлюза → телефон звонит через SIM
   на `X-GSM-To` → при ответе абонента должен быть слышен голос оператора.
3. Входящий: с сотового номера позвонить на SIM → телефон ставит INVITE в
   FreePBX → там звонит на абонента → абонент слышит звонящего.

### Если звука нет

| Симптом | Вероятная причина |
|---|---|
| Обе стороны молчат | Выбран акустический профиль, а не цифровой — смотрите `Selected profile:` в логе |
| Оператор слышит агента, агент не слышит оператора | Захват идёт не с `VOICE_DOWNLINK` (в аплинке собственная инъекция) |
| Агент слышит самого себя | Та же причина: использован `VOICE_CALL` вместо `VOICE_DOWNLINK` |
| Эхо | Акустический режим: телефонный микрофон попадает в аплинк |
| Шлюз не регистрируется | Неверный FQDN/порт/пароль; либо TLS-сертификат сервера без нужного SAN |
| Звонок «в никуда» | Не задан Own Number |

Логи приложения доступны в его UI; дополнительно:

```bash
adb logcat -s GSM2SIP:* AudioPolicy:* AudioFlinger:* 2>/dev/null | tail -100
```

## 6. Эксплуатация

- Телефон должен быть постоянно подключён к зарядке и к Wi-Fi (или к сети, из
  которой доступен FreePBX).
- Приложение работает как foreground service (`phoneCall|microphone`), переживает
  выключение экрана и стартует по `BootReceiver`.
- Если система убивает приложение в фоне — выдать ему исключение из оптимизации
  батареи:

```bash
adb shell dumpsys deviceidle whitelist +com.callagent.gateway
```

## 7. Откат

```bash
adb shell cmd role remove-role-holder android.app.role.DIALER com.callagent.gateway
# удалить модуль в Magisk Manager -> Modules -> Remove -> reboot
```

Удаление модуля возвращает телефон к стоковому состоянию: приложение исчезает,
системные privapp-права отзываются, `system.prop` и overlay-файлы модуля
удаляются. Прошивка при этом не затрагивается.
